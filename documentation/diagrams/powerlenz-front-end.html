PowerLenz Front End

From the incoming 230 V line to the ESP32-S3: where the CT and voltage transformer sit, what scales each signal, where the ADC reads it, and which three parts carry the isolation.

Which noise the filter can and cannot remove

Noise sourceRoughly how fastRemoved by Rf + Cf?
Switching power supplies (the AC-DC module, any DC-DC stage)tens of kHz to a few MHzYes, mostly
Sparks from motor brushes and relay contactsbroadband, up to hundreds of MHzYes, mostly
ESP32 clocks and SPI edgesMHz to hundreds of MHzYes, if the layout keeps it from coupling in
Wi-Fi transmit bursts pulling current from the supplyrepeat at low rates, tens to thousands of times a secondNo. Too slow. Fix with a separate analog LDO and careful layout.
50 Hz hum and harmonics coupled from nearby mains wiring50 Hz to a few kHzNo. This is the signal band. Handled by shielding, twisted leads and averaging in the DSP.

These ranges are typical and not measured on our hardware. Check the real noise on the first board with an oscilloscope.

How the numbers are calculated

The ADC only ever reads a voltage. Both channels carry a scaled-down voltage, and the firmware undoes the scaling to get volts and amps back. All values below are examples until the datasheets are checked. Values marked * come from my memory of the ADS131M04 and must be verified.

1. ADC code to volts

V_adc = code × Vref / ( G × 2^23 )

one count (LSB) = 1.2 V / 8,388,608 = 143 nV         (G = 1)

2. Current channel: volts to amps

I_sec  = V_adc / Rb                      (Ohm's law across the burden)
i(t)   = I_sec × N × k_i                 (the CT's ratio, then calibration)

in one line:
i(t)   = code × Vref/(G·2^23) × N/Rb × k_i

Check with the example: 156 mV peak ÷ 22 Ω = 7.1 mA, and × 2000 = 14.2 A peak, which is 10 A rms.

3. Voltage channel: volts to mains volts

v(t)   = V_adc × (R1+R2)/R2 × Nt × k_v

example: V_adc = 0.7955 V peak  →  × 16 × 25.56 = 325.3 V peak = 230 V rms

Divider sizing: at the highest mains voltage you want to handle (say 280 V rms), the secondary reaches 15.5 V peak, and the divider brings it to 0.97 V peak. That fits inside ±1.2 V with a little room to spare.

4. RMS, power and power factor

V_rms = sqrt( (1/M) × Σ v_k² )           M = samples in a whole number of cycles
I_rms = sqrt( (1/M) × Σ i_k² )           (160 samples per cycle at 8 kSPS)

P  = (1/M) × Σ ( v_k × i_k )             real power, watts
S  = V_rms × I_rms                       apparent power, VA
Q  = ± sqrt( S² − P² )                   reactive power, var (sign from lead or lag)
PF = P / S

energy (kWh) = Σ ( P × Δt ) / 3,600,000      Δt in seconds

Windows are cut at voltage zero-crossings, so each one holds whole cycles even when the grid drifts from 50 Hz.

5. The filter, and why the two channels differ

R_total = Rf + R_source
fc      = 1 / ( 2π × R_total × Cf )
gain    = 1 / sqrt( 1 + (f/fc)² )
phase   = − atan( f / fc )

current channel:  R_source ≈ Rb = 22 Ω
                  R_total  = 1,022 Ω   fc = 15.6 kHz   lag at 50 Hz = 0.184°
voltage channel:  R_source = R1 ∥ R2 = 938 Ω
                  R_total  = 1,938 Ω   fc =  8.2 kHz   lag at 50 Hz = 0.349°

The source resistance in front of the filter adds to Rf, so identical Rf and Cf do not give identical lag. This difference is a correction to what I said earlier about matching the two filters. The voltage channel lags by 0.165° more. For a load at power factor 0.5 that is about 0.5% error in P (0.165° = 0.0029 rad, times tan 60° = 1.73), until the phase calibration below removes it. A smaller R2, or a larger Rf on both channels, shrinks the gap.

6. Phase correction in firmware

delay = φ / ( 360° × f )                 φ = measured phase error between the channels

example: φ = 0.5°  →  0.5 / (360 × 50) = 27.8 µs
         sample period at 8 kSPS = 125 µs, so the shift is 0.22 sample

Because the shift is a fraction of a sample, the current samples are shifted by interpolating between neighbouring samples.

7. Range and resolution of the current channel

largest wire current, peak = (Vref / G) / Rb × N
                           = 1.2 / 22 × 2000 = 109 A peak = 77 A rms     (clips above this)

choosing Rb:   Rb ≤ (0.8 × Vref/G) / ( I_max,peak / N )
               for 40 A rms:  peak 56.6 A → 28.3 mA → Rb ≤ 0.96 V / 28.3 mA ≈ 34 Ω

smallest step: 143 nV / 22 Ω × 2000 = 13 µA of wire current per count (in theory)

The real low-current limit is much worse than 13 µA per count. It is set by noise, by the CT's accuracy and phase error at low current, and by layout. Measure it on the first board.

8. Calibration, in order

  1. Voltage gain k_v. Compare V_rms with a reference meter, and set k_v = V_ref ÷ V_measured.
  2. Current gain k_i. Use a resistive load (a heater or incandescent lamp) and set k_i = I_ref ÷ I_measured. Repeat at a few currents, because a CT is not perfectly linear.
  3. Phase φ. On the same resistive load, power factor must be 1 and Q must be 0. Adjust the current delay until it is.
  4. Check. Test a motor and a switch-mode supply against the reference. If P and PF agree, the calibration holds across load types.

Check before building

  • ADC input range. The divider and burden values depend on the ADS131M04's full-scale input and PGA gain. Confirm both in the datasheet, then size R1/R2 so the 325 V peak maps well inside range.
  • CT type. A current-output CT needs the burden resistor fitted and must never run open-circuit. A voltage-output CT has the burden built in and is safer for a first prototype.
  • Phase error. The CT and the transformer each add a small phase shift. Calibrate it out in firmware against a resistive load.
  • Supply split. Keep the analog 3.3 V LDO separate from the digital one, so Wi-Fi transmit bursts stay out of the ADC.
  • Mains safety. Use certified isolated modules, correct creepage and clearance, an enclosure, and have the board reviewed by someone with mains-design experience before it is powered.
